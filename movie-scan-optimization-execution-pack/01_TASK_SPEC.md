# 扫描机制优化任务规格

## 目标

把现有扫描明确拆成三种模式，并优化大目录的重复扫描性能。

### 模式 A：扫描当前文件夹

入口：左侧文件夹右侧的正常圆形刷新按钮。

要求：

- 只处理当前源文件夹，不扫描其他源文件夹。
- 先递归遍历整棵目录树，只读取目录结构和直属条目。
- 为每一级目录建立并持久化快照。
- 每个目录独立比较，不能因父目录未变化而跳过子目录检查。
- 仅对新增、删除、变化、无快照、上次未完成或存在未解决异常的目录，处理其直属视频。
- 对确认未变化且无异常的目录，不逐个读取视频详细属性，不重新运行无关元数据分析。
- 当前产品规则不考虑“同名文件覆盖但目录结构不变”的场景。

目录快照至少包含：

- `sourceFolderId`
- `directoryPath` / 规范化路径
- `parentDirectoryPath`
- `directoryMtime`
- 直属视频数量
- 直属子目录数量
- 直属条目摘要 `directEntryDigest`
- 上次成功扫描时间
- 上次扫描是否完整
- 是否存在未解决异常

`directEntryDigest`：将直属视频文件名和直属子目录名排序后生成轻量哈希。不要把深层后代条目混入当前目录摘要。

仅当以下条件全部满足时，才能跳过当前目录的直属视频扫描：

1. 本次目录读取完整成功；
2. 上次扫描完整成功；
3. 无未解决异常；
4. 目录修改时间一致；
5. 直属视频数量一致；
6. 直属子目录数量一致；
7. 直属条目摘要一致。

### 模式 B：重试异常项

入口：文件夹右侧三角形感叹号 → 异常弹窗 → “重试异常项”。

要求：

- 只处理该源文件夹尚未解决的失败文件和失败目录。
- 不扫描其他正常目录，不检查异常范围外的新文件。
- 文件异常：只重新执行失败阶段需要的处理。
- 目录异常：只重新遍历该失败目录及其子树。
- 单项成功后标记 resolved；再次失败时更新错误、时间和重试次数。
- 所有异常解决后，感叹号自动消失；仍有异常则继续显示。
- 异常记录必须跨应用重启持久化。

异常明细至少包含：

- `id`
- `sourceFolderId`
- `scanTaskId`
- `objectType: file | directory`
- 对象路径及规范化路径
- `failureStage`
- `errorCode`
- `errorSummary`
- `firstFailedAt`
- `lastFailedAt`
- `retryCount`
- `status: unresolved | retrying | resolved`
- `resolvedAt`

日志不得暴露真实完整路径；用户界面可以显示用户自己的路径。

### 模式 C：扫描全盘

入口：预览区域右上角“扫描全盘”。

要求：

- 范围保持不变：扫描所有启用的源文件夹。
- 继续按现有队列顺序执行，不改成无控制并发。
- 每个源文件夹复用“模式 A”的目录快照扫描逻辑。
- 全部完成后统一刷新。

## 上层接口必须分开

按项目命名规范实现语义明确的接口，类似：

- `scanSourceFolder(sourceFolderId)`
- `retryScanFailures(sourceFolderId)`
- `scanAllSourceFolders()`
- `getScanFailureSummary(sourceFolderId)`
- `listScanFailures(sourceFolderId)`

三种入口不得继续无差别落到同一个“全目录重扫所有视频”接口。底层读取、入库、对账等能力可以复用。

## UI 要求

- 正常刷新按钮始终保留，Tooltip 为“扫描当前文件夹”。
- 出现异常时，感叹号与正常刷新按钮同时存在。
- 感叹号只表示存在未解决异常。
- 异常弹窗按钮改为“重试异常项”，必须调用异常重试接口。
- 弹窗显示失败文件数、失败目录数、最近错误、最近失败时间、重试次数和明细。
- 右上角按钮文案或 Tooltip 明确为“扫描全盘”。
- 扫描中防止重复创建任务。

## 数据库迁移

使用项目现有迁移体系，至少新增：

1. 目录快照表；
2. 扫描异常明细表；
3. 必要的任务状态字段和索引。

要求：

- 无损升级已有数据库；
- 保留资料库、收藏、播放历史、待删除等现有数据；
- 用户无需清库或重新添加目录；
- 无历史快照时，下一次普通扫描自动建立；
- 沿用统一的 Windows/UNC/SMB 路径规范化规则；
- 同一路径不能因大小写、斜杠或尾部分隔符产生重复记录。

## 安全规则

- 根目录不可读：标记离线或失败，不清理已有记录，不做缺失对账。
- 子目录不可读：记录目录异常，继续处理其他目录，不把该目录视频误标记缺失。
- 只有目录枚举完整成功，才允许对该目录直属视频执行缺失对账。
- 只有父目录完整读取且明确缺少某子目录，才可判定子目录已删除。
- 扫描中断时，不提交未完成目录的成功快照，不解决未完成异常。
- 同一源文件夹同一时间只能运行一个修改扫描数据的任务。
- 普通扫描、异常重试、全盘中的子任务必须互斥，不能重复创建。

## 状态与进度

共享类型中明确区分扫描模式，例如：

- `current-folder`
- `retry-failures`
- `scan-all`

状态按现有架构扩展，建议包含：

- queued
- scanning-directories
- comparing-snapshots
- scanning-files
- retrying-failures
- paused
- completed
- completed-with-errors
- offline
- failed
- cancelled

普通扫描至少统计：检查目录、变化目录、跳过目录、处理视频、新增、更新、缺失、文件异常、目录异常。

异常重试至少统计：待处理、已处理、成功、仍失败。

全盘至少统计：当前文件夹序号、总文件夹数、已完成数、异常文件夹数。

## 自动化测试

必须补充并实际执行测试，至少覆盖：

### 目录快照

- 首次建立快照；
- 第二次未变化时不读取视频详细属性；
- 新增/删除/重命名视频；
- 新增/删除子目录；
- 深层子目录变化但根目录时间未变；
- 父目录未变仍检查子目录；
- 上次未完成或有异常时不得跳过；
- 条目顺序变化但内容相同不误判；
- 路径大小写和斜杠差异不生成重复快照。

### 异常重试

- 单个/多个失败文件只重试失败项；
- 失败目录只重扫该目录子树；
- 不扫描其他正常目录；
- 部分成功只解决成功项；
- 全部成功后感叹号消失；
- 重启后异常仍存在；
- 无异常时安全返回；
- 任务取消后未处理异常保留。

### 缺失安全

- 根目录离线不修改现有记录；
- 子目录失败不标记其视频缺失；
- 父目录完整成功且确认子目录删除时正确对账；
- 超时或权限失败不误判删除；
- 中断不提交不完整快照。

### UI / IPC

- 三个入口分别调用正确接口；
- 感叹号与刷新按钮同时存在；
- 异常数量正确；
- 重复任务被阻止；
- 同一源文件夹普通扫描与异常重试不能并发。

## 性能验证

增加可重复执行的基准测试，模拟：

- 10,000 个视频；
- 多级目录；
- 9,900 个成功记录；
- 100 个失败文件；
- 若干失败目录；
- 大部分目录未变化。

至少输出：读取目录数、视频详细属性读取数、跳过目录/视频数、数据库读写次数、耗时、异常处理数。

必须证明：

- 未变化目录不逐个读取视频详细属性；
- 异常重试不重新扫描正常的 9,900 个视频；
- 全盘仍按源文件夹顺序执行；
- 优化不破坏结果正确性。

## 代码质量

- 不留 TODO、FIXME、占位接口或空实现；
- 不只改 UI；
- 不无理由升级依赖；
- 保持锁文件一致；
- 不修改无关播放、重复项、封面、移动、删除、收藏逻辑；
- 新增接口必须有 TypeScript 类型；
- 数据库变更必须有迁移；
- 不泄露真实路径；
- 保持 Windows、本地盘、移动硬盘、NAS、SMB 兼容。
