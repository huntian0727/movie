# 映匣数据目录说明与维护手册

修订日期：2026-10-18（北京时间）。依据当日日常开发版代码及实际目录核对；自选目录迁移功能尚未进入公开 0.1.15 程序包，旧版请以对应版本教程为准。

这份文件解释目录的用途、保存内容、备份价值和清理边界。程序目录、资料库目录、原视频目录分别管理；绿色程序包携带程序主体，分享时不附带个人资料库、缓存、字幕或凭据。

普通用户可直接打开 **设置 → 数据存储位置 → 查看目录说明**，在程序内阅读离线用户版；本文件保留更完整的实现和维护细节。该入口属于尚未公开发布的开发版新增功能。

## 1. 先分清三个位置

| 位置 | 保存什么 | 如何找到 |
| --- | --- | --- |
| 程序目录 | EXE、app.asar、FFmpeg、播放器与 DLL 等运行组件 | 查看正在使用的桌面快捷方式目标 |
| 当前数据目录 | 资料库、应用设置、应用下载的字幕、封面/预览缓存、日志等 | **设置 → 数据存储位置 → 打开数据目录** |
| 默认 profile 目录 | 首次启动的数据位置；迁移后继续保留定位记录和 Electron 运行环境 | Windows 资源管理器地址栏输入下表对应路径 |

原视频通常在用户硬盘、NAS、挂载盘或 CloudDrive 来源内；扫描只建立索引，不把视频复制进资料库。视频旁的字幕、用户导出的 CSV/JSON 等仍在各自原位置。

| 程序身份 | 默认 profile 目录 |
| --- | --- |
| 日常开发版 / 原签名身份 | `%APPDATA%\local-video-manager` |
| 正式免费分享版及同社区身份候选 | `%APPDATA%\local-video-manager-community` |
| 隔离绿色测试版 | `%APPDATA%\local-video-manager-unsigned-test` |

未更改位置时，当前数据目录就是默认 profile 目录，下文两类内容可能混在一起。选定新位置后，程序在所选父目录中新建 `映匣数据-<profile目录名>`；此后主要数据在新目录，运行环境仍留在默认目录。默认目录没有清空是正常现象。不同身份不自动合并资料库；验收进程还可能使用单独指定的隔离目录。

## 2. 当前数据目录：总览

```text
当前数据目录/
├─ library.sqlite                   主资料库
├─ library.sqlite-wal               SQLite 正在使用的写入日志（可能出现）
├─ library.sqlite-shm               SQLite 共享内存索引（可能出现）
├─ library.sqlite.backups/          数据库升级前的快照
├─ settings.json                    应用设置
├─ clouddrive-credentials.bin       CloudDrive 加密凭据（配置后出现）
├─ subtitle-credentials.bin         字幕服务加密凭据（配置后出现）
├─ subtitles/                       应用下载的字幕与字幕选择记录
├─ media-cache/
│  ├─ covers/                       视频封面、图片缩略图
│  └─ timeline/                     时间轴预览帧
├─ logs/                            应用运行日志
├─ .data-directory-owner.json       发行身份归属
├─ .data-directory.lock             数据目录使用锁（运行期间）
├─ .data-migration-receipt.json      迁移校验凭据（迁移后可能出现）
├─ database-unclean-shutdown.marker  数据库运行状态标记（运行期间）
└─ 数据目录说明.md                  本说明的本地阅读副本
```

部分项目按需产生，缺少某个缓存目录或某项凭据不等于损坏；文件名以实际版本为准。以下“可再生成”均以原视频或服务仍可访问为前提。

## 3. 资料库、设置与凭据

| 名称 | 作用及内容 | 丢失影响 / 维护方式 |
| --- | --- | --- |
| `library.sqlite` | SQLite 主资料库：来源与视频索引、路径、元数据、收藏、播放记录及其他持久业务状态；也记录缓存引用、扫描和清理等业务数据 | 必须备份。重新扫描不能完整恢复收藏、历史及所有人工状态；其中不保存原视频本体 |
| `library.sqlite-wal` | SQLite WAL 写入日志，可能含尚未合并回主文件的最新事务 | 不单独删除；运行时只复制主库可能漏掉最新数据 |
| `library.sqlite-shm` | SQLite 为 WAL 协作维护的共享内存索引 | 由 SQLite 管理，不在程序运行时手工改动或删除 |
| `library.sqlite.backups/` | 数据库结构升级前的一致性快照，文件名形如 `library.sqlite.v14.<时间>.sqlite`；`v14` 表示备份时的 schema 版本 | 保留可验证的近期备份。只含数据库，不等于整个数据目录备份；不要随意替换当前库，旧程序也不能直接打开已升级的库 |
| `settings.json` | 应用功能设置，例如扫描/播放/预览、快捷键、网盘连接公开参数等；并非全部界面偏好 | 随资料库备份。不要从不明示例整份覆盖；历史版本或历史备份可能含敏感设置 |
| `clouddrive-credentials.bin` | 主进程保存的 CloudDrive 受保护凭据，如连接 Token | 属于敏感材料，不公开上传。使用 Electron safeStorage / Windows 用户保护机制，换机器或 Windows 用户后可能需重新配置 |
| `subtitle-credentials.bin` | 字幕服务所需的受保护 API Key、账号/密码或会话等，以实际配置为准 | 同样单独加密；不会因为文件是二进制就适合分享。换环境后可能需要重新登录 |

备份/恢复前正常退出程序。若异常退出后仍存在 WAL/SHM，应保留整套文件，让程序或专业 SQLite 工具按一致性流程处理，不能通过删除 WAL“修复数据库”。

## 4. subtitles：应用下载的字幕

```text
subtitles/
└─ <视频ID的SHA-256>/
   ├─ selection.json
   └─ <字幕UUID>.srt / .ass / .vtt
```

每个视频使用独立子目录，长字符串是视频 ID 的哈希，不是片名。字幕文件为应用下载并保存的内容；`selection.json` 记录字幕条目、服务来源、语言、下载时间、当前选择和字幕时间偏移等，并以视频大小/修改时间识别版本。

这里属于有保留价值的数据，建议随主库备份。删除后可能丢失已下载字幕、选择和时间偏移；不能保证原服务仍能重新提供同一字幕。视频文件夹里原有的同名字幕不属于这里，切换应用数据目录不会移动它们。

## 5. media-cache：封面与预览缓存

| 子目录 / 文件形式 | 内容 | 维护说明 |
| --- | --- | --- |
| `media-cache/covers/<缓存键>-<秒数>s.jpg` | 从视频截取的封面图 | 可从原视频重新生成；丢失后首次展示可能更慢 |
| `media-cache/covers/still-v1-<缓存键>.jpg` | 目录浏览中的静态图片缩略图 | 可从原图片重新生成 |
| `media-cache/timeline/<缓存键>/<毫秒数>.jpg` | 某视频在相应时间位置的时间轴预览帧 | 大目录可能占用较多空间；重新生成会再次读取视频 |

缓存键根据媒体路径、大小和修改时间生成，用于区分文件版本，不是原视频内容的完整哈希。路径看起来像乱码通常是正常设计，不宜人为改名。

程序有媒体缓存容量、过期和保留策略；维护优先使用程序现有缓存管理入口，并遵守保留项。需要手工整理时先退出、确认是缓存副本并备份必要内容。删除磁盘图片后，数据库中的缓存引用不会因手工删除立刻全部同步，可能暂时缺图并需要重建。网盘媒体重建会产生读取、网络流量和等待。

**`media-cache` 与 Electron 的 `Cache` 是两套目录。** 旧版本曾使用 `cache/covers` 和 `cache/timeline`；Windows 大小写不敏感，旧 `cache` 可能与 `Cache` 合在一起。兼容逻辑只处理其中明确的 `covers`、`timeline`，不能据此删除整个 `Cache`，尤其不能把 `Cache_Data` 当作视频封面目录。

## 6. logs：排查问题的运行记录

`logs/app.jsonl` 是当前日志，一行一个 JSON 事件；滚动文件通常为 `app.1.jsonl`、`app.2.jsonl` 等，记录时间、级别、模块、操作及错误等信息。当前默认单文件上限约 5 MiB，最多 5 份并按 14 天保留规则管理，具体行为以当版代码为准。

日志不代替资料库备份。排查故障时保留对应时段；分享前检查私人路径、错误上下文等，即便程序有脱敏也不要直接公开整个目录。日常优先让日志组件自动轮换，不在运行时删除正在写入的文件。

## 7. 目录定位、迁移及运行标记

| 名称 / 所在位置 | 记录什么 | 维护规则 |
| --- | --- | --- |
| `data-location.json` / **固定默认 profile 目录** | `version` 格式版本、`current` 当前数据目录；迁移时可能有 `pending` 计划、`cleanup` 待清理状态及 `message` 提示 | 迁移后的关键定位入口，保持原位并备份；它不随主数据移动。不要手改或删除，否则可能无法找到原资料库 |
| `.data-directory-owner.json` / 当前数据目录 | 格式版本和所属发行 profile | 用于防止跨身份误用；不是 Windows 账户口令。恢复已有目录时需要它，不要改名、修改或删除 |
| `.data-directory.lock` / 当前数据目录 | 进程 PID 与随机占用标识 | 防止多进程同时使用资料库；正常退出会释放，异常残留由程序检查。锁存在不表示数据损坏，不按时间长短直接删 |
| `.data-migration-receipt.json` / 迁移目标 | 迁移 ID、源/目标路径、文件清单、大小和 SHA-256 校验值 | 用于迁移恢复和原文件清理，可能在完成后保留；包含私人路径，不公开。迁移/清理未结束时不要编辑或删除；不是完整备份 |
| `database-unclean-shutdown.marker` / 当前数据目录 | 数据库尚处于使用状态的标记 | 正常关闭后移除；异常退出后用于触发下次启动检查。运行中出现正常，交给程序处理 |
| `.movie-migration-<UUID>/` / **目标父目录** | 未发布的迁移暂存副本 | 中断可能留存；与正式目标不同。确认当前库正常、无待处理迁移且不再需要恢复后再核实处理，不按名字批量删除 |

迁移采用白名单，不会移动用户放在根目录里的所有文件。当前清单是：`library.sqlite`、对应 WAL/SHM、`library.sqlite.backups`、`settings.json`、两种 `*-credentials.bin`、`subtitles`、`media-cache`、`logs`、`.data-directory-owner.json`；另兼容旧 `cache/covers`、`cache/timeline`。运行锁、数据库状态标记会由新进程管理，迁移目标生成新的校验凭据。

因此手工导出的文件、手工命名备份、任意自建文件夹，以及本次附上的 `数据目录说明.md`，当前均不在自动迁移白名单内。再次迁移后，本说明和自建资料需另行复制；不要误认为新目录里应当自动包含全部旧文件。

迁移复制与校验通过后才切换定位，正常打开资料库后再按原文件校验结果清理。原文件有变化、被占用或权限异常时可能保留；看到旧副本不代表可以直接删除。新磁盘不可用时，使用程序的“重新定位已有资料库”，选择含 `library.sqlite` 和归属标记的已有目录，不新建空文件冒充原资料库。

## 8. 默认 profile 内的 Electron 运行环境

以下主要由 Electron/Chromium 创建。名称和细节会随版本变化，本应用不逐文件维护其内部格式；迁移后仍保留在默认目录。有些保存界面状态，不能把这一整组都当成随时可清的垃圾。

| 名称 | 作用 / 保存内容 | 维护建议 |
| --- | --- | --- |
| `Cache/`，常见 `Cache_Data/` | 页面运行所需的 Chromium 资源缓存；旧版本还可能混有应用 `covers`、`timeline` | 与媒体缓存分别判断，不整目录当作视频缓存删除 |
| `Code Cache/` | JavaScript 等代码运行相关缓存 | 交给运行环境管理；不是应用源码或用户文档 |
| `GPUCache/` | 图形渲染缓存 | 不是封面图或原视频，故障排查时再按明确方案处理 |
| `ShaderCache/`、`GrShaderCache/` | 图形着色器相关缓存 | 同上，目录存在不代表正在使用某一种硬件加速模式 |
| `DawnGraphiteCache/`、`DawnWebGPUCache/`、`GPUPersistentCache/` | Chromium 图形组件的持久缓存 | 内部实现随版本变化，不手工改内容 |
| `Local Storage/`，常见 `leveldb/` | 渲染页面的本地持久状态；当前应用在这里保存目录手动排序、菜单折叠、卡片/侧栏尺寸、每页数量、最近目录等偏好 | 不是 `settings.json` 的替代品；删除可能重置界面偏好。想完整保留使用习惯时一并保留默认 profile |
| `Session Storage/` | 页面会话存储 | 由 Electron 管理，不等于主库内的播放历史 |
| `Network/` | Chromium 网络层的数据，例如 Cookie 等，按实际版本/使用情况产生 | 可能含会话信息；不公开，不因“缓存”二字整体删除 |
| `blob_storage/` | 浏览器 Blob 对象相关存储 | 不是本应用原视频存档目录；不据此承诺其中任意历史文件都可删除 |
| `Dictionaries/` | 运行环境字典相关资料 | 不是个人字幕目录，由 Electron 管理 |
| `Shared Dictionary/` | Chromium 内部共享字典相关数据 | 与字幕文本无关，具体格式由运行环境决定 |
| `shared_proto_db/` | Chromium 内部的共享存储 | 不是映匣的 `library.sqlite`，不按业务数据库方式维修 |
| `VideoDecodeStats/` | Chromium 视频解码相关统计 | 不是用户收藏或播放历史，也不是视频内容 |
| `Local State`、`Preferences` | Electron/Chromium 的运行配置和内部状态 | 不等于应用业务设置；迁移后仍可能更新，保持原位 |
| `DIPS`、`DIPS-wal` | Chromium 内部数据库及配套日志 | 不属于业务 SQLite 资料库，不能凭后缀判断修复方式 |
| `SharedStorage` | Chromium 内部存储文件 | 以运行环境管理为准，不手改 |
| `declarative_performance_observer.db`、`declarative_performance_observer.db-journal` | Chromium 内部数据库及事务文件 | 非应用业务资料；具体内部字段未在本项目维护 |
| `DevToolsActivePort` | 某些调试/启动方式留下的端口信息文件 | 不是用户设置；仅凭残留文件不能认定当前调试端口仍开放，不公开其中连接信息 |
| `lockfile` | 运行环境使用的锁文件 | 与 `.data-directory.lock` 不同，不在程序运行时手动删除 |

本次本地核对时，上述名称均在默认目录中实际出现。说明覆盖职责边界，未逐项解析 Chromium 私有数据库。其他版本可能增加或减少这些项；新出现的未知文件先核实来源。

## 9. 历史遗留与非标准文件

| 本次观察到的项目 | 已确认事实 | 后续处理 |
| --- | --- | --- |
| 默认目录中的 `native-player/libmpv-2.dll` | 当前代码的播放器从程序 `resources/native-player`（开发时 `native-bin`）加载；未发现当前代码引用这处 AppData 路径 | 记录为待核实的历史播放器材料，不作为主库或缓存处理；核实旧快捷方式、旧程序与文件来源后再决定保留/归档 |
| `library.sqlite.before-empty-folder-fix-20260802` | 非标准命名文件，不是当前 `library.sqlite`，不在迁移白名单和当前升级备份命名规则内 | 不能仅凭名字证明它是有效备份或可删；需单独验证、确认价值后归档处理 |
| 默认目录中剩余的 `media-cache/timeline/` | 本次迁移后仍能看到该目录；仅凭目录存在无法判断为空、旧缓存、清理保留或旧进程重新生成 | 先核对当前定位与进程；不要用它推断迁移失败，也不要据名称直接删除 |
| 自建文件、其他备份、导出文档 | 不是程序明确管理的标准项目 | 默认保留，逐项确认内容和归属；自动迁移不搬走任意文件 |

本说明记录用途，不执行上述历史材料的清理，也未检查这些历史文件的正文或有效性。

## 10. 备份、恢复与分享

### 日常完整数据备份

1. 在设置中确认当前数据目录，正常关闭所有使用该库的程序，等待进程退出；不要强制结束来代替正常关闭。
2. 复制整个当前数据目录到独立备份位置，保留数据库及仍存在的配套文件、设置、字幕、凭据和归属标记。空间紧张时可另行规划可重建缓存，但先明确排除影响。
3. 迁移后同时备份默认目录的 `data-location.json`；若要保留全部界面偏好，还需保留默认 profile 的运行状态材料。恢复时不要拿一份过时定位记录直接覆盖现有记录。
4. 原视频、旁置字幕、用户导出文件另做备份；资料库或缓存都无法恢复被删除的原视频。
5. 记录备份时间、程序身份/版本和原路径；在副本上验证可用性，再决定是否淘汰旧备份。

换电脑或 Windows 用户后，原绝对路径可能不可用，加密凭据也可能无法解开；需要重新定位来源或重新登录。数据库升级备份仅用于相应恢复方案，回退应使用升级前的完整数据备份，不直接让旧程序打开新 schema。

### 本工作区的开发备份与“保留三份”约定

开发快照在数据目录之外，由 `scripts/project-backup.ps1` 创建，包含源码 bundle、checkpoint、SQLite 一致性快照、设置及工具支持的凭据材料，并有 manifest 校验。当前脚本不是整个数据目录镜像，不能把它当作字幕及全部附件的完整备份。

本地 `cleanup-backups.ps1` 按已授权策略验证并保留最近三份开发快照；数据库升级备份单独保留三份，旧程序存档和安装包各三份。它是维护脚本运行时执行的策略，不是应用后台定时清理，不因任务标签不同而无限保留。新增数据种类时应同时检查备份工具是否覆盖。

### 分享绿色程序包

只分享正式打包的程序内容。不要把当前数据目录、默认 profile、开发快照、日志、字幕、缓存或凭据文件塞进 ZIP；即使视频本身不在其中，路径、历史、字幕选择和账号材料也属于个人数据。

## 11. 常见维护问题

| 现象 / 目标 | 先检查与处理 |
| --- | --- |
| 更改位置后 AppData 仍占空间 | 检查 `data-location.json` 指向及当前设置；运行环境、历史副本、保留的旧文件仍可能在默认目录。先统计分类，再处理具体项 |
| 想腾空间 | 先看 `media-cache` 和程序缓存管理，再看日志与已验证旧备份；不要从删除主库、WAL、字幕或定位记录开始 |
| 启动后看起来像新资料库 | 核对程序身份、实际快捷方式和当前目录，保护原库；不要立即重新扫描覆盖现场，尤其不要删除定位记录 |
| 数据盘暂时离线 | 先恢复磁盘连接；必要时使用“重新定位已有资料库”。不要创建假的空库让程序通过检查 |
| 迁移后旧目录还有文件 | 检查 pending/cleanup 提示、是否有其他进程及未纳入白名单的手工文件，确认原因后再处理 |
| 字幕不见了 | 分清旁置字幕和应用下载字幕；核对 `subtitles` 与对应主库是否来自同一份备份 |
| 想把说明带去下一处目录 | 本地 `数据目录说明.md` 是阅读副本，当前不会自动迁移；迁移成功后单独复制说明及自建文档 |
| 出现未列出的新目录 | 记录名称、位置、产生版本，在代码中查创建者；未确认前保留，不直接套用“缓存可删”结论 |
