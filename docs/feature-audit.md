## 详细自查

### 1. 文件夹导入与扫描

**当前实现**
- `src/main/ipc.ts` 提供 `folder:add` 和 `folder:scan`。
- `src/main/media/fileDiscovery.ts` 负责发现视频文件。
- `src/main/media/libraryScanner.ts` 读取文件 stat、metadata，并调用 repository upsert。
- `VideoRepository.getVideoByPath` 和 scanner 的跳过逻辑避免未变化文件重复 ffprobe。
- 缺失目录或消失文件会标记 missing。

**风险**
- 启动同步仍可能扫描大量文件路径，虽然跳过 ffprobe，但极大目录仍有 I/O 成本。
- 没有进度反馈，用户可能误以为卡住。

**建议修复/优化**
- P1：增加扫描中状态和文件夹级进度。
- P2：启动同步改成延迟后台任务，并限制并发/频率。

### 2. 视频列表基础展示

**当前实现**
- `LibraryShell` 提供视图切换、搜索、排序。
- `VideoGrid` 和 `VideoTable` 展示不同视图。
- `Toolbar` 文案已恢复正常中文。

**风险**
- 表格视图部分文案可能仍存在旧编码问题，需要整体检查。
- 视图排序在前端完成，对超大库会有 CPU 成本。

**建议修复/优化**
- P1：检查并修复 `VideoTable` 乱码。
- P2：未来可把搜索/排序/分页下推到 SQLite。

### 3. 分页

**当前实现**
- `LibraryShell` 使用 `PAGE_SIZE_OPTIONS = [100, 200, 300]`。
- 默认 `100`。
- 视图、搜索、排序、文件夹、页大小变化后回到第一页。
- `LibraryShell.test.tsx` 覆盖分页行为。

**结论**
- 符合当前需求。

### 4. 视频封面预览图与缓存

**当前实现**
- `local-video://cover/{videoId}`。
- `mediaProtocol` 使用 `buildCacheKey(video.path, video.sizeBytes, video.modifiedAt)`。
- 缓存文件存在时直接返回。
- 缓存文件不存在时排队调用 `generateCover`。
- 同一输出路径有 `pendingImageGenerations` 去重。

**风险**
- 现在没有把生成成功的 `cover_cache_path` 写回数据库，封面展示依赖协议缓存，而不是 DB 状态。
- 封面生成失败只返回 404，前端显示 img 加载失败后的默认背景需要真实验证。
- 当前 `net.fetch(..., { headers })` 的 `headers` 是请求头，不等价于响应缓存头；浏览器是否按预期缓存需要桌面端验证。

**建议修复/优化**
- P1：前端 img 加载失败时隐藏破图，显示默认占位。
- P1：协议返回图片时如需缓存头，应构造 Response 或确认 Electron protocol 对 `net.fetch` 的缓存行为。
- P2：生成成功后可更新数据库缓存状态。

### 5. 独立播放窗口

**当前实现**
- `src/main/playerWindow.ts` 维护单个 `playerWindow`。
- `video:open-player` IPC 触发打开/复用。
- 播放窗口始终使用固定 `player=1` URL，不在 query 中携带 video id 或完整队列。
- 主进程把原始队列限制为最多 300 条，去重并保证选中项存在，再按数据库当前记录过滤未知或磁盘缺失文件。
- renderer 先订阅带 sequence 的领域事件，再读取会话快照；初始化期间只补放比快照新的事件。

**风险**
- 播放窗口复用时不再整页 `loadURL`；会话保存在主进程内存中，应用完全退出后不会恢复上次队列。
- 播放窗口关闭再打开、连续切换、当前项被删除和扫描同时发生时的真实视觉体验仍需验证。
- 没有为播放窗口设置专门的窗口图标或保存窗口尺寸。

**建议修复/优化**
- P1：桌面端验证窗口复用、关闭重开、300 条队列与当前项删除后的相邻项选择。
- P2：如未来需要跨应用重启恢复队列，应单独设计持久化版本与过期/缺失清理，不能恢复未经主进程重验的路径。

### 6. 播放能力

**当前实现**
- `shared/playbackRouting.ts` 按扩展名选择 native/mpv。
- `video:play-external` 使用 mpv。
- 原生播放器 `onError` 会尝试 mpv。
- `ipc.ts` 在 mpv 启动失败后调用 `shell.openPath(video.path)`，尝试交给系统默认播放器。

**风险**
- mpv 不在 PATH 时会进入系统默认播放器 fallback，而不是只显示 mpv 错误。
- “主流各种格式”实际依赖 Chromium 原生能力、本机 mpv 或 Windows 文件关联。
- `shell.openPath` 的成功只表示系统接受打开请求，不证明目标播放器最终成功解码；错误文案、窗口切换和无文件关联场景需要验证。

**建议修复/优化**
- P0/P1：检测 mpv 是否安装，并在设置页或错误提示中明确说明。
- P1：增加“用系统默认播放器打开”作为最终 fallback。

### 7. 播放控制

**当前实现**
- `PlayerPage` 支持播放/暂停、快进/快退、音量、静音、上一部/下一部、收藏、全屏。

**风险**
- 外部 mpv 路由时，内置进度条、音量、快进/快退被禁用，和“统一播放器体验”的期望有差距。
- 收藏、播放历史、视频更新/删除和资料库重扫已有主进程领域事件同步；事件不持久化，正确性依赖“先订阅、后快照、按 sequence 去重”协议。

**建议修复/优化**
- P1：用真实双窗口高频收藏/取消、标记、删除和重扫验证精确失效范围及视觉稳定性。
- P2：若要控制 mpv，需要改成 mpv IPC 模式，当前只是外部窗口启动。

### 8. 进度条 hover 预览

**当前实现**
- hover 时计算时间，按 5 秒粒度生成预览 URL。
- `local-video://preview/{videoId}/{timeMs}` 生成帧并缓存。
- 图片失败后前端记录失败 URL，继续显示时间。

**风险**
- 用户已经反馈“进度条预览异常”，必须真实复测。
- 预览帧生成时机可能造成第一次 hover 延迟。
- 如果 ffmpeg 无法解析某些格式，预览帧会失败。

**建议修复/优化**
- P1：手测 mp4/mkv/avi 各至少一个样本。
- P1：加 loading 占位，而不是只有时间。
- P2：预生成少量关键帧改善首次 hover 延迟。

### 9. 收藏

**当前实现**
- `video:favorite` 持久化。
- 列表和播放器均可切换。

**风险**
- 自动同步已实现，但真实双窗口快速收藏/取消、窗口关闭重开和操作失败不发布事件的体验仍需验证。

**建议修复/优化**
- P1：桌面端采集双窗口连续操作证据；若发现遗漏，优先补领域事件发布点和查询失效测试，不要回退到在 URL 传业务状态。

### 10. 删除与重命名

**当前实现**
- `renamePreservingExtension` 和 `permanentlyDeleteFile`。
- 操作后更新/删除数据库记录。
- UI 有确认和错误展示。

**风险**
- 文件被播放器占用时删除/重命名会失败，需要确认错误提示可理解。
- 同名冲突处理需要验证。

**建议修复/优化**
- P1：手测占用文件删除/重命名。
- P2：错误文案更友好。

### 11. 最近播放

**当前实现**
- `play_history` 表以 `video_id` 为主键。
- `recordPlayback` upsert，同一视频只保留最新。
- “最近播放”视图按 `listPlayHistory` 顺序展示。

**风险**
- 只记录开始播放，未记录播放到哪里。
- `positionMs` 预留但未在播放进度变化/关闭时更新。

**建议修复/优化**
- P1：播放窗口关闭或定时更新播放进度。
- P2：最近播放卡片显示“上次播放时间/进度”。

### 12. 设置与维护

**当前实现**
- 设置页存在默认递归、启动同步、快进快退秒数、播放策略、缓存位置、清理缓存、缺失文件。

**风险**
- 缓存清理后正在加载的图片请求可能返回失败，需要验证 UI 自动恢复。
- 设置页部分行为缺少端到端验证。

**建议修复/优化**
- P1：手动验证缓存清理后重新生成封面/预览。

## 当前最可能不符合预期的事项

1. P1：当前已采用 native → mpv → 系统默认播放器 fallback；mpv 不可用时会调用 `shell.openPath`，但三段降级的真实桌面体验和错误提示仍需验证。
2. P1：多窗口同步已实现自动化覆盖，但真实双窗口高频操作和视觉稳定性仍未验证。
3. P1：进度条预览已做缓存和失败降级，但用户反馈异常，需要真实视频复测。
4. P1：封面失败时前端可能显示破图，需要桌面端确认。
5. P1：最近播放还未记录播放进度，只记录播放时间。
6. P2：部分旧组件可能仍有乱码文案，尤其 `VideoTable`。
