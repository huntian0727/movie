# 视频网格瀑布流布局设计

- 日期：2026-07-14
- 主题：所有视频网格页改为瀑布流布局
- 状态：已确认，可进入实现

## 背景

当前视频库网格页已经支持封面预览、收藏、重命名、删除、详情和打开播放页等能力，但在“按视频真实比例显示封面”后，横屏视频会在卡片下方留下明显空白。这个问题在混合比例视频库里会比较突出：竖屏视频显示正常，横屏视频却显得卡片结构松散，浏览时的视觉节奏不稳定。

前一轮修复已经确认，封面文件本身没有被裁切，问题主要来自网格卡片的固定外框与真实比例封面之间的冲突。因此，这次不再继续微调单个封面容器，而是直接调整整个网格布局模型。

## 设计目标

1. 消除横屏视频封面下方的大块空白。
2. 保持竖屏视频和特殊比例视频的完整显示，不再强行压入固定比例容器。
3. 不改变现有搜索、排序、分页、文件夹筛选和详情等业务行为。
4. 让所有网格页保持一致的浏览体验，避免同一类视图在不同入口下表现不一致。

## 方案选择

本次在三个方向中做过取舍：

1. 统一卡片高度，图片完整显示，空白区域用背景填充。
2. 改为瀑布流布局，按真实比例展示封面。
3. 横屏和竖屏使用两套固定比例规则。

最终选择方案 2，并将范围确定为全部网格页，包括：

- 所有视频
- 收藏
- 文件夹
- 最近播放

选择理由：

- 最能直接解决“横屏下方大块空白”问题。
- 不牺牲竖屏和特殊比例视频的完整性。
- 用户在不同入口下看到同一种网格体验，学习成本更低。

## 交互设计

“网格视图”入口保持不变，不新增额外切换按钮。用户进入任意网格页时，看到的仍然是当前熟悉的卡片式浏览模式，只是卡片排布从规则等高网格改为瀑布流列布局。

每张卡片保持统一宽度，封面区域按视频真实宽高比渲染。横屏视频自然更矮，竖屏视频自然更高，避免再用固定 `16:9` 外框包住所有视频。卡片内的标题、元信息和操作按钮继续保留现有结构，详情、收藏、重命名、删除等交互位置和行为不变。

这次不引入新的排序逻辑，也不在瀑布流中插入分组标题或比例标签，避免额外增加认知负担。

## 实现建议

优先采用纯 CSS 的多列瀑布流实现，而不是先引入额外布局库或手写列高分配逻辑。原因是当前 `VideoGrid` 已经具备稳定的卡片循环结构，分页也已经把单页元素数量控制在可接受范围内，用 CSS 做第一版改造可以把风险压到最低。

建议实现方式：

- 外层视频容器从当前等高 `grid` 调整为多列布局
- 每个卡片增加 `break-inside: avoid`
- 卡片宽度保持统一，由列数控制整体密度
- 封面区域使用视频真实比例，避免再次引入固定高度占位
- 信息区与操作区尽量保持现有 DOM 结构，减少测试面变化

## 组件范围

首选将改动收敛在 renderer 层：

- `src/renderer/components/VideoGrid.tsx`
  - 保持视频卡片循环结构
  - 如有需要，为瀑布流容器补充语义化 class
- `src/renderer/styles.css`
  - 承担主要布局改造
  - 配置多列数、列间距、断点和卡片防拆分策略
- `src/renderer/components/LibraryShell.tsx`
  - 原则上不改业务逻辑
  - 仅在确有必要时补充视图容器类名或状态传递

这次不计划改动主进程、数据库、扫描逻辑和缓存生成流程。

## 响应式策略

桌面端采用多列布局，列数根据可用宽度收缩。建议先从保守规则开始，例如：

- 宽屏：4 列
- 中屏：3 列
- 窄屏：2 列
- 更窄场景：1 列

目标是先保证浏览稳定，不追求一次把所有断点调到极致。后续如果需要更细致的视觉打磨，再根据实际使用情况微调列宽和间距。

## 风险与控制

### 1. 视觉阅读顺序变化

CSS 多列布局的视觉流与传统 `grid` 不完全一致，浏览时更接近“按列向下”。这会改变部分用户的扫视习惯。

控制方式：

- 保持搜索、排序、分页逻辑不变
- 先在现有分页规模下上线，避免一次展示过多卡片

### 2. 卡片交互错位

卡片高度变化后，需要确认封面点击、悬浮层、详情按钮和收藏按钮都没有错位。

控制方式：

- 尽量不改卡片内部 DOM 结构
- 重点回归按钮点击和悬浮样式

### 3. 极端比例视频拉高列高

很窄或很长的视频会显著拉高单张卡片高度，影响整列节奏。

控制方式：

- 第一版先允许真实比例展示
- 如后续出现明显体验问题，再补封面最大高度兜底策略

## 测试建议

建议重点覆盖以下回归点：

1. 所有网格页都使用同一种瀑布流容器样式。
2. 卡片在分页、搜索、排序和文件夹筛选后仍能正常渲染。
3. 点击封面打开播放页的行为不变。
4. 详情、收藏、重命名、删除按钮仍然可点击且位置正确。
5. 横屏视频不再出现封面下方大块空白。
6. 竖屏视频和特殊比例视频保持完整显示。
7. 窄屏下列数能自动收缩，不出现重叠或裁切。

## 非目标

这次设计明确不包含以下内容：

- 改造为虚拟化瀑布流
- 新增独立的“瀑布流/网格”双模式切换
- 调整搜索、排序或分页规则
- 重做卡片信息层级和操作按钮结构
- 修改封面生成、时间轴预览生成或数据库字段

## 推荐结论

对当前项目来说，最合适的方案是：

- 保留现有网格视图入口
- 将全部网格页统一改为瀑布流布局
- 按视频真实比例展示封面
- 以纯 CSS 多列布局作为第一版实现

这样可以直接解决横屏视频封面下方空白过大的问题，同时保住竖屏视频的完整显示，并把实现风险控制在主要是 renderer 样式层的范围内。
