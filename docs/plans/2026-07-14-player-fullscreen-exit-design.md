# 播放页全屏退出与控制层设计

## 背景

当前播放页已经支持进入全屏，但交互只依赖浏览器 Fullscreen API 的基础行为。用户进入全屏后，如果不知道可以按 `Esc`，会很容易感知为“无法退出”。同时，全屏状态下现有控制条没有为沉浸式观看重新组织，导致退出路径不明显，快进、快退、上一部、下一部、进度条等核心操作也缺少一致的全屏体验。

## 目标

本次设计聚焦三个目标：

1. 让用户在全屏状态下始终能找到明确的退出路径。
2. 保留现有播放器核心能力，不因为进入全屏而改变使用方式。
3. 以最小改动落在 `PlayerPage` 和对应样式中，不扩散到全局状态。

## 交互方案

进入全屏支持两种方式：点击现有“全屏”按钮，或在视频画面区域双击。退出全屏支持三种方式：按 `Esc`、点击右上角“退出全屏”按钮、在视频画面区域再次双击。双击仅绑定在视频显示层，不覆盖详情弹窗、进度条和底部控制条，避免误触。

全屏状态下，顶部和底部控制层改为浮层模式。默认淡出，鼠标移动时显示。顶部浮层保留返回、标题信息，并新增明确的“退出全屏”按钮。底部浮层继续承载进度条、上一部、下一部、快进、快退、播放暂停、音量和全屏按钮，布局尽量沿用当前非全屏模式，降低学习成本。键盘行为保持一致：`Space` 播放/暂停，左右方向键快进快退，`Esc` 退出全屏。

## 状态与实现

`PlayerPage` 内部维护 `isFullscreen` 与控制层显示状态，所有进入/退出动作统一走同一个 `toggleFullscreen()`。组件监听 `fullscreenchange`，确保用户通过 `Esc` 或系统方式退出时，界面状态能同步更新。控制层自动隐藏逻辑仅在全屏时启用；当鼠标位于控制层、正在拖动进度条或操作音量时，不提前隐藏。

## 风险与回归点

主要风险包括：

- 双击进入/退出全屏与单击播放/暂停冲突。
- 控制层自动隐藏与进度条拖动冲突。
- `jsdom` 对 Fullscreen API 支持有限，需要以调用验证和状态同步为主。

回归重点包括：

- 全屏进入、退出和 `fullscreenchange` 状态同步。
- 顶部浮层“退出全屏”按钮可用。
- 双击画面可进入/退出全屏。
- 全屏时快进、快退、上一部、下一部、进度条、音量保持可用。
- 详情弹窗打开时不被双击或 `Esc` 误伤。
