## Context

真实资料库约 34 万条视频，其中约 29 万条处于元数据待分析或失败状态。元数据异常页面原先在 Electron 主线程同步执行三次大范围 SQLite 查询；扫描失败关联缺少与 `object_path` 匹配的索引，单次页面加载实测约阻塞 17.6 秒，并在元数据更新事件触发刷新时重复产生磁盘读取。

## Changes

- 将元数据异常分页查询接入现有 Asset Center 只读 Worker，查询期间不再阻塞 Electron 主线程消息循环。
- 新增 schema v13 迁移，为活动扫描失败记录增加 `(source_folder_id, object_path, failure_stage)` 精确查询索引；不修改业务数据和现有表字段。
- 将分类统计、筛选结果总数和分页数据所需 SQL 从三条降为两条，并只计算一次分类状态。
- 对元数据后台更新引发的页面刷新增加 1.2 秒尾随合并，避免短时间连续完成任务时反复提交全页查询。
- 扩充性能门禁，覆盖 32 万视频和 5,000 条活动元数据失败记录，并验证查询只执行两条 SQL。

## Verification

- TypeScript 类型检查和生产构建通过。
- 完整 Vitest：72 个测试文件、657 项测试全部通过。
- 元数据异常性能门禁：32 万视频、5,000 条活动失败记录，第一页查询约 418 ms、2 条 SQL，低于 3 秒预算。
- 元数据异常 Repository、只读 Worker 路由、IPC 契约、数据库迁移和 Renderer 页面测试均通过。
- 打包冒烟检查会同时从主连接和实际发布版只读 Worker 查询元数据异常页，确认打包后的 Worker 协议与结果一致。

## Risks and follow-up

- 首次启动新版本时会执行一次 schema v13 索引迁移；迁移框架会先为现有数据库创建可恢复备份，大型资料库首次启动可能比平时慢。
- 查询仍会读取 SQLite 数据，但已在只读 Worker 中隔离，不会再卡住前端。后续若异常记录继续显著增长，可再增加按筛选条件缓存统计的优化。
- 本次没有修改视频扫描、媒体分析、播放、文件删除或 CloudDrive API 业务逻辑。
