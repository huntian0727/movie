架构分析和页面数据契约已经完成。本次为资产中心与播放诊断中心输出详细 UI 设计和 ASCII 原型，优先级为实用性、信息效率、美观。

- 新增 docs/ai/ui-design/playback-diagnostic-design.md。

- 资产中心采用连续指标带、双栏状态区和服务端分页资料库列表。

- 记录 Native、MPV、扫描异常、重复候选和文件夹视图的复用入口。

## Design decisions

- 设计判断：面向单人高频使用的 Windows 桌面工具，延续现有深色、紧凑、功能优先的视觉语言。
- 设计参数：DESIGN_VARIANCE 3、MOTION_INTENSITY 2、VISUAL_DENSITY 8。
- 不采用商业 SaaS 仪表盘风格，不增加渐变、玻璃效果、发光、装饰图表或无意义动画。
- 不引入新的 UI 框架、字体或图标库，继续复用现有 CSS 和 Lucide。
- 在线状态明确为“基于最近扫描”，不伪装成实时网络监控。
- 播放诊断只展示规则分析结果，不使用“保证可以播放”等承诺性文案。

## Risks and follow-up

- 风险：映射盘无法仅根据数据库路径可靠区分本地磁盘和 NAS，UI 必须使用“本地 / 挂载盘”或后续增加只读驱动器类型检测。
- 风险：播放风险数量需要新增只读规则聚合，不能在 renderer 中加载全量视频计算。
- 风险：元数据状态卡如果需要直达筛选，必须新增 UI 查询参数；在目标筛选完成前不能提供无效跳转。
- 下一步建议：先实现 Asset Center 的只读 DTO、聚合查询和来源分页，再实现静态页面。
- 下一步建议：Playback Diagnostic 先实现数据库缓存快速诊断，最后独立增加可取消的深度检测任务。
