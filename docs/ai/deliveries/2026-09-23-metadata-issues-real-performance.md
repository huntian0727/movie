# 元数据任务真实大库性能与状态表达优化

## Context

真实资料库约 34.5 万条视频时，“元数据异常”页面每次打开和筛选会重复对约 29 万条待处理记录执行完整分类与排序，主进程查询约需 4.0–4.4 秒。页面和资产中心又把等待分析与真实分析失败合称为“异常”，使大量正常排队或策略暂缓记录看起来像损坏数据。

## Changes

- 保持扫描、播放、数据库结构和元数据处理策略不变。
- 元数据任务统计使用一次物化的重复大小集合，避免逐记录相关子查询。
- 明细分页先取得各真实状态数量，再按“分析失败、待自动分析、暂缓分析”的既有顺序，仅查询当前页实际覆盖的类别；跨类别页会自动拼接且不漏行、不重复。
- 资产中心新增待分析、分析失败的独立只读统计字段；总数仍保持兼容。
- 将界面“自动候选 / 策略暂缓 / 元数据异常”调整为“待自动分析 / 暂缓分析 / 元数据任务”，资产中心显示待分析与失败的具体数量。
- 增加跨类别分页回归测试，并更新模块说明。

- `npm run test:packaged-smoke`、`npm run test:installer-smoke`：PASS；包括真实 worker 元数据任务查询、renderer 挂载、预览缓存与安全边界。

## Risks and follow-up

- 选择“暂缓分析”时仍需要构建重复大小集合并对大类别排序，真实库首次查询约 2.0 秒；它已脱离渲染线程且不会读取视频内容。后续若继续优化，应优先考虑短周期只读统计缓存，不应新增数据库架构或改动扫描策略。
- 新增的资产中心细分字段来自现有 `videos.metadata_status` 聚合，不修改持久化结构。
