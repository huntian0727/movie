## Context

重复项页面原先只支持按单个文件大小改变方向，且当前页还会在 Renderer 中再次排序。用户需要按一个候选组包含的重复文件数量排序，以便优先处理副本最多的候选组，同时保留按容量等其他实用指标排序的能力。

## Changes

- 新增重复项排序依据：可释放空间、单个文件大小、重复数量、视频时长，并支持从高到低和从低到高。
- 默认行为继续保持“单个文件大小，从高到低”，不改变用户原有打开页面时的顺序。
- 排序由只读数据库 Worker 分页查询完成，不把全部重复组加载到 Renderer。
- 按重复数量排序时，以可释放空间、文件大小和时长作为稳定的并列排序条件。
- 切换排序依据或方向后回到第一页，目录筛选和优先保留目录继续生效。
- 候选组摘要改为“共 N 份 · 计划保留 1 份 · 可删除 N 份 · 可释放容量”，便于直接判断清理价值。
- 移除当前页的重复前端排序；候选组严格按数据库返回顺序显示，组内文件按文件名稳定排列。

## Risks and follow-up

- “可释放空间”和“可删除数量”按当前 CloudDrive API 可删除候选计算；缺少远端身份的文件不会被误计入可删除数量。
- 旧调用未提供排序字段时仍回退到按单个文件大小排序，避免影响已保存的后台任务或旧版请求。
- 本次没有修改重复判定、文件删除、扫描或数据库结构。
