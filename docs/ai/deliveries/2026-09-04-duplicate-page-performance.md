# 0.1.12 重复项页面性能与单一优先保留目录

## Context

真实资料库约有 32 万条视频、3.1 万组重复候选和 9,430 个候选目录。重复项页面原先会分别执行候选统计、完整重复统计、当前页身份和目录统计，多次扫描同一批数据；目录选择器打开时还会渲染全部目录。更严重的是 0.1.11 将全局资料库刷新序号接入重复查询后，每个后台元数据完成事件都会重新执行整页查询，造成页面持续卡顿和大量磁盘读写。用户同时确认优先保留规则只需要一个当前目录，新选择替换旧选择，并包含所有子目录。

## Changes

- 重构 `listDuplicateGroupsPage`：物化活动任务保留身份与可选筛选身份，只分组一次，并通过窗口统计同时取得总组数、候选文件数、可删除数、预计空间和当前分页。
- 未按目录筛选时移除无意义的自包含 `IN` 子查询；按目录筛选时保留原有“只要组内任一文件命中目录，就显示整个候选组”的语义。
- 候选目录统计复用活动任务身份，并增加 60 秒进程内缓存；翻页和切换排序不再重新生成数万条目录选项。
- 将重复项数据刷新从全局资料库事件中拆分：元数据进度不再刷新重复页面；重扫仍立即刷新；连续删除事件以 250ms 合并，删除结果仍能迅速消失但不会逐文件重复查询。
- 优先保留目录改为单一持久规则：数据库读取仅返回最近启用项，保存新目录时事务内删除旧记录，清除当前目录时一并清理旧历史。
- UI 仅展示一条“当前优先保留目录”，提供更换和清除；成功完成“全部筛选结果”批量删除且没有失败或跳过时，自动清除该规则、取消目录筛选并回到第一页。失败或取消继续保留规则。
- 目录选择器仍搜索全部入库目录，但最多渲染 200 条匹配项，并提示继续输入关键词。
- 安装器 smoke 严格从 `package.json` 解析当前版本并检查对应 NSIS 文件，修复历史安装包共存时误选最旧文件的问题。
- 版本更新至 0.1.12；不修改重复判定契约、CloudDrive API 删除语义、扫描架构或数据库 schema。

## Risks and follow-up

- 目录候选计数最多可能延迟 60 秒更新；重复组、删除数量和当前分页仍直接读取数据库。该缓存只影响目录选择器辅助统计，不改变删除计划。
- SQLite 查询仍在 Electron 主进程同步执行；本轮已将真实资料库后续分页降至亚秒级并消除刷新风暴。若资料库继续显著增长，可后续评估只读 worker，但不在没有新证据时引入第二套数据库访问架构。
- 真实 CloudDrive2 删除 E2E 需要用户数据与远端文件，会产生不可恢复操作，本轮不自动执行。
