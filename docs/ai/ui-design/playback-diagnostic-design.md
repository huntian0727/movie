# 播放诊断中心页面设计

## 设计定位

播放诊断中心用于回答“为什么这个视频可能播放不了”。它展示数据库已有信息和规则分析结果，不承诺视频一定能播放，也不把播放器选择规则包装成真实硬件解码测试。

设计优先级：

1. 首屏直接给出规则结论。
2. 用户可以看懂结论依据。
3. 原始字段完整但不抢占主视线。
4. 打开页面不产生网盘读取。

视觉参数与资产中心一致：

- DESIGN_VARIANCE: 3。
- MOTION_INTENSITY: 2。
- VISUAL_DENSITY: 8。
- 沿用现有深色主题、Segoe UI Variable、橙红强调色和 Lucide 图标。
- 不增加新设计系统和装饰性视觉。

## 页面入口

### 独立菜单入口

在左侧主导航中增加“播放诊断”，建议位于“最近播放”之后、“扫描异常”之前。

首次进入且没有指定视频时，显示视频选择界面：

- 最近播放。
- 搜索视频。
- 风险视频筛选。

独立入口适合主动排查文件，也允许连续切换多个视频。

### 视频详情入口

在 VideoDetailsDialog 底部操作区增加“播放诊断”按钮。

- 传入当前 videoId。
- 直接显示该视频的快速诊断。
- 不经过搜索页。
- 关闭诊断后返回原来的详情上下文。

### 播放器入口

在 PlayerPage 的信息操作区域增加“诊断”按钮。

- 定位当前 selectedVideoId。
- 打开诊断后保持播放器会话不变。
- 不自动暂停或切换当前播放。

## 页面布局

页面分为顶部工具栏、诊断结论、详细信息和操作区。

### 顶部区域

左侧：

- 标题：播放诊断。
- 当前文件名。
- 次级路径，单行中间省略。

右侧：

- “更换视频”按钮。
- “重新读取缓存”图标按钮。
- 当前结果时间，例如“基于 16:28 的资料库信息”。

“重新读取缓存”只重新读取数据库，不启动 FFprobe。

### 诊断结论区域

结论是页面第一视觉重点，使用单个横向结果面板，不拆成多张卡片。

面板内容：

- 主结论：建议使用内置播放器、建议使用 MPV、信息不足、文件缺失、读取失败。
- 置信度：高、中、低、未知。
- 一句话原因。
- 当前播放偏好：自动、Native 优先、MPV 优先。
- 规则依据摘要，最多三项。

示例：

    建议使用 MPV
    规则依据：HEVC 视频 + DTS 音频，当前 Native 兼容规则不匹配。
    这是规则分析结果，不保证实际播放结果。

结论颜色：

- Native 推荐：低饱和青绿色。
- MPV 推荐：现有橙红强调色。
- 信息不足：黄色。
- 文件缺失或读取失败：红色。

颜色之外必须显示文字和图标。

### 详细信息区域

宽屏使用左右两栏：

- 左栏约 58%，展示文件、视频和音频信息。
- 右栏约 42%，展示播放分析和建议。

窗口小于 1050px 时按顺序纵向排列。

#### 文件信息

采用两列字段组，不使用逐行全边框表格。

必须展示：

- 文件名。
- 路径。
- 大小。
- 修改时间。

补充展示：

- 文件扩展名。
- 来源类型。
- 资料库。
- 是否缺失。
- CloudDrive 远端身份状态。

路径默认一行中间省略。点击路径复制完整路径，旁边提供“在文件夹中显示”图标按钮。

#### 视频信息

必须展示：

- 格式。
- 视频编码。
- 分辨率。
- Profile。
- Pixel Format。

补充展示：

- 时长。
- 时长来源。
- 元数据状态。
- 编码探测状态。

字段值区分三种语义：

- 有值：直接显示。
- 尚未采集：显示“尚未采集”。
- 探测失败：显示“读取失败”，并提供已有重试入口。

不能将 null 统一显示为“无”。

#### 音频信息

V1 只展示当前已保存的首音轨编码：

- 音频编码。
- 详细音轨信息状态：尚未采集。

声道、采样率、码率、语言和多音轨必须等到按需深度检测后再显示。

#### 播放分析

分析区固定展示：

- 当前规则选择：native 或 mpv。
- 当前用户偏好。
- 容器判断。
- 视频编码判断。
- Profile 判断。
- Pixel Format 判断。
- 音频编码判断。
- 数据完整性判断。

每项依据使用“支持 Native”“倾向 MPV”“中性”“未知”四种文本状态。不要使用百分比分数或大进度条。

#### 播放建议

最多展示三个建议，按可执行性排序：

1. 使用当前策略播放。
2. 使用 MPV 播放。
3. 补充元数据或检测详细媒体信息。

文件缺失时不显示播放按钮，改为“查看扫描异常”。

## 规则分析文案

### Native 推荐

    建议使用内置播放器
    MP4 容器、H.264 High Profile、yuv420p 和 AAC 音频符合当前 Native 规则。
    这是兼容规则判断，不代表已经验证硬件解码。

### MPV 推荐

    建议使用 MPV
    HEVC 视频或 DTS 音频不符合当前 Native 规则，外部播放器通常更合适。
    这是规则分析结果，不保证一定可以播放。

### 信息不足

    暂时无法给出可靠建议
    当前缺少视频编码或像素格式，结论只能依据文件扩展名。
    可以先补充元数据，也可以直接尝试 MPV。

### 文件缺失

    文件当前不可用
    资料库已将该记录标记为缺失，无法进行文件级检测。
    请先在扫描异常中确认文件状态。

## 组件拆分

    PlaybackDiagnosticPage
    ├─ PlaybackDiagnosticToolbar
    ├─ DiagnosticVideoPicker
    │  ├─ DiagnosticSearch
    │  ├─ RecentVideoList
    │  └─ RiskVideoList
    ├─ DiagnosticResultPanel
    ├─ DiagnosticDetailGrid
    │  ├─ FileInformationSection
    │  ├─ VideoInformationSection
    │  ├─ AudioInformationSection
    │  ├─ PlaybackEvidenceSection
    │  └─ PlaybackAdviceSection
    └─ DiagnosticProbePanel

| 组件 | 职责 | 禁止行为 |
| --- | --- | --- |
| PlaybackDiagnosticPage | 选择视频、加载快照、处理 stale 状态 | 自动读取文件 |
| DiagnosticVideoPicker | 服务端分页搜索与最近播放 | 加载封面或完整资料库 |
| DiagnosticResultPanel | 展示规则结论和免责声明 | 宣称保证播放 |
| InformationSection | 展示字段与空值语义 | 自行运行 ffprobe |
| PlaybackEvidenceSection | 展示规则依据 | 改写实际播放器路由 |
| PlaybackAdviceSection | 调用现有播放和定位入口 | 复制播放器启动代码 |
| DiagnosticProbePanel | 管理按需深度任务 | 阻塞页面或修改资料库 |

## 交互说明

### 视频选择

- 输入搜索词后使用服务端分页，不在前端过滤全量视频。
- 搜索结果只显示文件名、路径、大小和时长，不加载预览图。
- 从最近播放选择时复用现有播放历史。
- 选择新视频后立即清除上一个视频的操作状态，但可保留布局骨架。

### 播放

- “按当前策略播放”调用现有 openPlayer。
- “使用 MPV”调用现有 playExternalVideo。
- 不在诊断页实现新的播放路径。
- 启动失败时沿用现有错误处理，不将本次规则结论改成播放保证。

### 查看位置

- 使用现有 revealVideoInFolder。
- renderer 只传 videoId，不传任意路径给主进程。
- CloudDrive 或缺失文件无法定位时显示局部错误。

### 重新读取缓存

- 重新请求单个视频的数据库诊断快照。
- 不运行目录扫描。
- 不调用 CloudDrive API。
- 不读取视频内容。

### 深度检测

作为次要折叠区域，按钮名称为“检测详细媒体信息”。

- 用户点击后才创建后台 job。
- CloudDrive 文件先提示可能产生网络读取。
- 任务可取消、超时、失败。
- 完成后显示详细视频流、音频流和字幕流。
- 结果绑定 videoId、sizeBytes 和 modifiedAt。
- 文件版本变化后显示“结果已过期”，不继续使用。
- V1 可仅保存在内存，不要求数据库迁移。

## 页面状态

### 未选择视频

- 显示搜索框。
- 显示最多 10 条最近播放。
- 显示“从视频详情也可以直接进入诊断”。

### 加载

- 保留标题和已选文件名。
- 结论区显示固定高度骨架。
- 详细字段按最终分组显示骨架，不使用全屏 spinner。

### 数据不足

- 仍展示现有文件字段。
- 结论为“信息不足”。
- 明确列出缺失字段。
- 提供“补充元数据”和“尝试 MPV”，但不自动执行。

### 文件更新

- 收到当前 videoId 的 video:updated 后标记结果过期。
- 300-500ms 合并后重新加载快速诊断。
- 深度结果只有文件版本一致时才继续显示。

### 文件移除

- 收到 video:removed 后立即显示“记录已移除”。
- 禁用播放、定位和深度检测。
- 保留返回或更换视频入口。

### 错误

- 快速诊断失败时显示局部重试。
- 深度检测失败不清空快速诊断。
- 不显示异常堆栈、环境变量或 ffprobe 原始输出。

## 视觉规范

- 结论区只使用一个高优先级面板。
- 文件、视频和音频使用分组区块与留白，不使用三张同尺寸商业卡片。
- 规则依据使用紧凑两列表达，不使用评分环、百分比或进度条。
- 主操作最多一个强调按钮，其他操作使用普通或图标按钮。
- 路径、编码和像素格式可以使用现有系统等宽字体回退，不新增字体依赖。
- 所有按钮桌面端保持单行，图标和文字间距沿用现有控件。
- 没有自动动画。状态变化只做轻量颜色和透明度反馈。

## 窗口适配

- 1200px 以上：详细信息左右两栏，右侧分析区可在内容区域内 sticky。
- 1050-1199px：左右两栏缩窄，字段标签固定宽度。
- 小于 1050px：结论、文件、视频、音频、分析、建议依次纵向排列。
- 独立页面的搜索选择器最大宽度 720px，避免搜索结果横向过散。

## 性能验收

- 打开快速诊断做到 0 次视频读取、0 次目录遍历、0 次 CloudDrive 请求。
- 首屏只传输单个定长诊断 DTO。
- 搜索结果服务端分页且不加载封面。
- 只有当前视频的 Domain Event 会刷新诊断。
- 深度检测完全后台化，可取消，不阻塞导航和现有播放器。
- 规则分析与当前 choosePlaybackRoute 结果一致。

## 规则边界

页面允许展示：

- 当前规则选择。
- 选择原因。
- 元数据完整程度。
- 建议使用的播放器。

页面禁止展示：

- “保证可以播放”。
- “硬件一定支持”。
- “MPV 一定可以解码”。
- 没有数据依据的成功率。
- 未被系统记录的播放失败次数。
