## 已实现的源码

| 工作包 | 实现 | 保持的边界 |
| --- | --- | --- |
| 超大 API 目录 | 每批最多 128 条、约 8ms 处理预算，批间让出主线程 | 只有完整枚举及处理完成后才进行缺失对账和完成 Snapshot；取消不错误标记缺失；不逐视频 stat |
| 重复清理准备 | Worker 只读正式库计算候选，在私有临时文件预生成任务行；串行受理、幂等 requestId | 不写正式库、不创建可执行任务、不删除文件；主连接重新校验并原子提交 |
| 查询队列 | 同一等待查询合并；窗口 ID＋用途＋查询类型隔离，替换该消费者的旧等待查询 | 不强行中断运行中的 SQL，不跨窗口取消，其他消费者仍保留共享查询 |
| 缓存失效 | schema 14 内部事务计数与触发器，按 library/sources/scan/cleanup/tasks/playback/images 分类 | 所有连接的写入受跟踪；未知提交、计数异常、缺失触发器和 schema 变化保留完整失效兜底 |
| 翻页统计 | 普通视频计数最多 64 个缓存；重复项最多 2 套轻量排序结果 | 页内 VideoRecord 每次读取最新值；图片、播放历史、任务进度不使无关重复排序失效 |
| 启动维护 | 主窗口先显示，全面缓存核查延后 15 秒；缓存保留路径查询复用只读 Worker | 维护不会被取消，只是避开启动和播放启动保护；仍有后台磁盘开销 |
| 媒体资源调度 | 截图与时长/元数据解析共用 2 个读取槽；同一远端来源最多 1 个，支持优先级和排队取消 | 不改变播放器核心；不读取完整 SHA；已有远端截图限并发保留 |
| 列表渲染 | 距可见区域约 600px 以内挂载重内容，离屏用实测高度占位 | 有焦点的操作保留；选择和截图展开状态留在父组件；网格和巨大单组尚未改成真正虚拟化 |
| 任务写入开销 | 每条 SQL 最多 50 行，最宽 900 个绑定变量；同一事务内合并 cleanup/tasks 计数 | SQL 批次不是多个事务；后续批次失败会连同前面批次、计数和占用全部回滚 |
| 超大任务受理 | 主连接 SQL JOIN 重验及 INSERT SELECT 原子复制临时计划 | 不添加竞争正式库写锁的 worker；失败完整回滚，临时计划不能恢复执行 |
| 选中项查询 | 导出/删除范围用 json_each 单参数集合在 SQL 过滤 | 保留筛选及排序，不读取未选中记录，不受大量 ID 的绑定变量限制 |
| API 目录缓存 | LRU 最多 256 个目录、100,000 个 entry，超大单次 listing 不缓存 | 不改变 Snapshot；失败/取消不写缓存，手动强刷仍绕过缓存 |

内部计数不是业务数据副本，没有新增第二套扫描数据库、没有改变视频业务字段。任务进度与文件占用使用不同域，避免每次后台进度重算重复项。合并计数的临时掩码只存在于已有原子事务内，提交前恢复；崩溃/失败时随事务回滚，其他连接看不到半成品。

IPC 仍使用既有通道。分页读取新增可选 `purpose` 字符串（1..64 字符，仅小写字母、数字、连字符，默认 `default`）；主进程以真实 `event.sender.id` 生成隔离作用域。视频主列表、目录选择器、目录预览和播放列表采用不同用途。

## 实际测量

`scripts/verify-background-workers.mjs` 创建独立临时资料库，仅生成文件元数据；不创建媒体、不启动删除执行器。覆盖真实编译后的候选 Worker、分页 Worker、版本变化拒绝、任务原子受理、幂等及占用隐藏。

| 实验 | 候选准备 | 原子入库/主循环最大停顿 | 结果 |
| --- | --- | --- | --- |
| 初版 2,000 组 | 121ms | 56ms | 正确性及 1 秒响应门槛通过 |
| 初版 32,000 组 | 1,140ms 左右 | 2,645ms | 正确性通过；响应门槛 FAIL |
| 单计数记录＋事务边界合并，逐行 SQL，32,000 组 | 1,149ms | 2,162ms | 正确性通过；响应门槛 FAIL |
| 中间版本 50 行 SQL 批次，32,000 组 | 1,155ms | 1,451ms | 正确性通过；响应门槛 FAIL，未交付 |
| 对照：移除计数触发器的独立模拟库，逐行 SQL，32,000 组 | 1,161ms | 950ms | 用于定位计数/写入开销；不是生产配置 |
| SQL 批次版本，2,000 组 | 121ms | 入库 60ms，主循环 61ms | 正确性及响应门槛 PASS |
| SQL 批量复制，32,000 组 | 1,215ms | 入库及主循环 540ms | 正确性及响应门槛 PASS |
| 最后代码与全量回归同时运行，32,000 组 | 1,532ms | 入库及主循环 674ms | 正确性及响应门槛 PASS |
| 最后代码，50,000 组 | 2,088ms | 入库及主循环 985ms | 正确性及响应门槛 PASS；接近上限，不视为 p95 |

以上是单机实验，不是正式资料库 p95，也不保证不同磁盘/目录/组大小达到同样速度。对照模式只在脚本创建的临时资料库内执行，不对正式库移除触发器。脚本保留失败断言，没有提高门槛或把失败写成通过。

最终采用临时计划＋SQL 批量复制，避免候选大对象跨线程拷贝及主线程逐行生成 UUID/绑定参数。临时计划只包含本次候选的期望版本和任务行，主服务创建并持有路径，Renderer 无法指定路径；它不是第二套扫描数据库，没有 queued job。主连接在一个 immediate 事务内重验文件版本、核对计划数量、检查占用、创建 job、复制全部明细和占用。正常完成及失败后删除服务自己创建的临时目录；进程崩溃留下的临时计划不能执行，只有正式库完整提交的任务能按原规则恢复。

最终压力门槛已达标，但原子 SQL 复制仍有短暂停顿，不宣称零卡顿或任意数据量性能保证。临时计划包含路径，只保存本机临时目录，不进入 GitHub、日志或备份源码。
