## 已实施的源码优化

| 环节 | 原开销 | 本轮实现 | 保持的边界 |
| --- | --- | --- | --- |
| 异常中心分页 | IPC 在 Electron 主线程执行同步 SQL | 复用 AssetCenter 只读 Worker；同一读取事务完成统计和分页 | 原 IPC、字段、筛选和分页语义不变；不增加数据库结构 |
| 目录异常状态维护 | 每个异常反复加载来源下全部异常并在 JS 中查找 | 两个 EXISTS 查询，只找当前目录和直接文件；复用 normalized_path 索引范围 | 子目录异常不错误归入父目录；未解决及重试中状态均保留 |
| 单个对象异常解决 | 先加载整个来源，再过滤目标路径 | 按来源、规范化路径、可选对象类型查询匹配记录 | 各 failure stage 的解决语义不变 |
| 资产/目录/视频浏览查询队列 | 每次请求直接发入 Worker 的消息队列，包括相同刷新 | 每个服务一次只派发一个读取；相同的等待请求共享后续一次结果 | 不合并执行中的查询；不同参数不取消、不替换；出错/退出/关闭拒绝所有等待调用 |
| 截图生成调度 | 每选一个任务，都对全部等待任务排序，并反复分配数组 | 单次线性遍历选择最高优先级，FIFO 处理同优先级 | 总并发、远端并发、共享订阅、取消和播放启动让路逻辑不变 |
| 缓存维护 | 剩余条目计算用 removedPaths.includes，最坏为 N×M | 用 Set 查询已移除路径 | 配额、受保护文件、删除失败及状态通知不变 |
| 侧栏拖动 | 每次 pointermove 更新整个页面，宽度变化同步写 localStorage | 每帧至多更新一次宽度；停止拖动时保存最终宽度 | 鼠标释放/取消、键盘调整、尺寸限制及持久化不变 |
| 重复项卡片 | 全部卡片接收整份保留选择表和新建回调，memo 失效 | 每卡片只接收自己的 keepVideoId，复用稳定回调 | 原保留计划、单项清理、播放、详情及目录入口不变 |

查询合并键为操作和完整参数的 JSON；入队前复制参数，防止调用者修改等待请求。仅合并还没有开始的相同查询，避免“刷新”复用写入前启动的旧查询。不同窗口/组件的不同查询均保留；相同查询可共享尚未启动的读取结果。本轮没有实现按窗口和消费者取消旧查询，没有声称所有查询的总排队长度已硬性受限。

目录索引范围使用 `[normalizedDirectory + '\\', normalizedDirectory + ']')`；在现有规范化路径的二进制索引中，反斜杠紧邻右方括号之前。避免 LIKE 默认大小写行为导致前缀扫描，也使 `%`、`_`、`!` 保持字面含义。回归测试用 EXPLAIN QUERY PLAN 验证了直接文件查询采用现有 normalized_path 索引范围，不新增索引或迁移。

## 尚未实施：需要下一批独立验证

1. **精准缓存失效**：继续保留 data_version 的完整失效兜底。不能仅凭 Renderer 事件跳过失效；必须覆盖主连接及独立写连接，避免导航/重复项计数过期。
2. **按消费者取最新查询**：需要窗口、页面/选择器、操作三个维度的标识和取消约定。本轮只做安全的相同等待请求合并，不会跨组件取消查询。
3. **大量清理任务准备**：同步准备及写入仍可能阻塞。后续将计算移出主线程前，必须保持预留、任务和条目持久化的原子性，不允许半成品删除任务。
4. **超大 API 单目录写入及目录预取**：事务时间分片、暂停与预取上限需单独验证取消/错误时不错误标记缺失；不改变 CloudDrive listing fast path。
5. **少量选中项的导出/ID查询**：把选择范围下推 SQL，需要验证过滤、排序、排除项及大规模选择的 SQL 参数上限。
6. **巨大单个重复组、视频网格/列表真虚拟化**：需在空闲时检查滚动、焦点、选择及播放队列。本轮仅减少卡片无关重绘。
7. **共享预览状态订阅、目录缓存 LRU、异步日志和启动缓存维护**：需要错误反馈、终止、过期及恢复的独立设计，暂不混入低风险修改。
