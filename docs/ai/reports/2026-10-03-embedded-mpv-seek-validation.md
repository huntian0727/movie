# 内嵌 MPV：seek 与控制恢复定向验证

## 结论

本轮 14 个真实挂载盘 4K HEVC 场景及 4 个合成格式场景通过有界恢复检查。证明该隔离原型可以恢复播放，不能证明上轮失败已永久修复或已具备正式发布条件。上轮失败报告保留，不以本轮成功覆盖负面证据。

发现两项明确问题：仅检查 `time-pos` 会把尚在读取的 seek 误判为完成；实际 UI 的 Space / Esc 未送达实验动作接口。云盘读取/缓存等待存在明显波动，但未做本地同文件对照，不能确定唯一根因，也没有证据支持全局关闭硬解。

正式 `src/`、扫描器、数据库 schema、播放器调用、安装包和快捷方式均未修改。本次交付是实验及验证文档；**桌面版本尚未交付**。

## 范围与方法

- 基线 commit：`edb45510d8e28a40157b98d35c45cebb4ba058b6`；分支 `ai/embedded-mpv-seek-validation`。
- Windows / Electron 33.4.11；mpv `v0.41.0-1092-g3186d369f`，沿用上轮固定 DLL。来源、哈希及最小验证见 [前次报告](2026-10-03-embedded-mpv-spike.md)。未新增正式依赖。
- 使用同一个匿名 `cloud-hevc-aac` 样本：3840×2160，261,428,404 bytes，27.698 秒，HEVC + AAC，经既有 F: 挂载路径读取。
- 每个场景创建新宿主，不并行解码。未清理挂载端缓存，未建立整片本地副本，未测冷缓存或网络带宽；短片播放/挂载预读可能读完整片。
- 开始检查：已加载、取消暂停、无待完成 seek、实际进度超过 0.6 秒且有视频尺寸。正常 seek：同一 token、进度在目标 ±0.35 秒内、`seeking=no`、播放重启计数增加。
- 组合串行场景：第二轮额外等待每次旋转引发的重启结束；重叠场景故意仅等 `time-pos` 更新后继续旋转/全屏，用于隔离旧测试缺陷。
- 恢复：无待完成 seek、非用户暂停、实际进度增加 >0.6 秒，再观察 700ms；不等同持续流畅或声画实测。加载上限 45s、正常 seek 30s、恢复推进 15s，超限报告 FAIL 并释放宿主。

[MPV 官方手册](https://mpv.io/manual/master/) 对 `seeking` 和 `playback-restart` 的定义支持区分时间位置更新与播放重启完成。计数和属性采样不是实际显示帧/声音采集，不能代替端到端音画验收。

## 第一轮：八场景对照

单位 ms；开始包含宿主启动与初始播放推进，恢复包含 700ms 观察。旋转当时每次仅观察 300ms；后续重复轮加强串行等待。非 seek 场景标为 —。

| 场景 | 实际解码 | 开始 | seek | 恢复验证 | 结果 |
|---|---|---:|---:|---:|---|
| 基线 | d3d11va | 3388 | — | 4339 | PASS |
| 仅 seek | d3d11va | 1108 | 3257 | 3907 | PASS |
| 仅旋转 | d3d11va | 1105 | — | 1448 | PASS |
| 仅全屏/恢复 | d3d11va | 9635 | — | 1444 | PASS |
| seek 后立即旋转/全屏 | d3d11va | 15565 | 184（仅位置更新） | 7099 | PASS |
| 串行组合 | d3d11va | 6205 | 9781 | 1754 | PASS |
| 仅 seek，软件解码 | no | 19431 | 14203 | 8455 | PASS |
| 串行组合，软件解码 | no | 4776 | 8738 | 1565 | PASS |

关键证据：重叠场景 184ms 时 `time=5`，但 `seeking=yes`、restartCount 仍为 1；后续两次旋转也没有完成播放重启。旋转单独场景引发两次额外 seek/restart，而全屏单独场景不增加计数。因此控制序列需要独立管理“提交成功”与“媒体就绪”。

软解也通过，但 seek 可达 14.203 秒。硬解不是本轮唯一必要故障条件；加载从约 1.1 秒到 19.4 秒变化。没有同文件本地对照，不能归因于解码器或网盘某个具体设置。

## 第二轮：重叠/串行交替，各三次

| 次数 | 场景 | 开始 ms | 严格 seek ms | 恢复验证 ms | 结果 |
|---|---|---:|---:|---:|---|
| 1 | 重叠 | 3144 | 未单独等待 | 12956 | PASS |
| 1 | 串行 | 5821 | 3870 | 1758 | PASS |
| 2 | 重叠 | 4369 | 未单独等待 | 7286 | PASS |
| 2 | 串行 | 7619 | 5917 | 1691 | PASS，有缓存等待 |
| 3 | 重叠 | 6430 | 未单独等待 | 4840 | PASS |
| 3 | 串行 | 8231 | 1415 | 5135 | PASS |

串行通常缩短“发出继续播放以后”的等待，但 seek 和旋转等待被前置，不能声称总耗时必然缩短；不同缓存状态也会混淆比较。第二次串行虽然满足实际推进，最后采样 `pausedForCache=yes`、cacheDuration≈0.0167s，表明 PASS 不是“无缓冲”。12.956 秒的恢复接近既定超时，本轮不足以宣称上轮问题已消除。

整轮 998 个 renderer 心跳；main 最大额外延迟 14.84ms、renderer 16.50ms（基准间隔 100ms）。第一轮 main 15.15ms，尚未装 renderer 心跳。说明隔离宿主的这些等待没有明显阻塞本原型 JS 线程；不代表正式项目所有页面性能通过。

## 合成媒体与实际界面

四个本地 12 秒、640×360、24fps 测试媒体全部通过：H.264/AAC MP4、HEVC/AAC MP4、HEVC/DTS MKV、VP9/Opus MKV，包含中文与空格路径。严格 seek 分别 128、186、124、187ms；嵌入、尺寸、暂停稳定、音量属性、旋转、全屏/恢复、播放推进均通过。实际硬解 d3d11va，记录掉帧为 0；不代表 4K 长片质量。

自动模拟自有宿主被终止，Electron 存活；新宿主重新播放成功；最终退出码 0、宿主正常清理。整轮 main 心跳最大额外延迟 20.88ms，renderer 14.80ms。

使用 computer-use，仅操作中性合成视频的隔离窗口：

- 画面可见；全屏按钮生效；继续按钮后进度从 0 到 12 秒；退出按钮生效，宿主 exit code 0；最终窗口清单只有原有正式“拉面影视”。
- Space 没改变暂停，Esc 没退出全屏；动作记录仅含 fullscreen、pause(false)、quit，没有键盘产生的动作。焦点/跨原生窗口键盘路由尚未解决，不能标为通过。
- `currentAo=wasapi` 仅证明音频输出模块已初始化。实际声音、主观音画同步 NOT RUN。

## 推荐下一步与发布边界

1. 若继续验证，先在隔离原型验证键盘焦点转发、快速多次 seek 的最新请求合并、就绪/读取等待状态；保持宿主隔离。
2. 同文件本地/挂载对照可帮助区分读取与解码，但需用户另行授权完整本地副本。当前没有执行复制或缓存清空。
3. 然后再测真实长片 4K、字幕/多音轨、HDR、实际声音、持续缓冲与长时间资源增长。不能以 27 秒短片证明全部云盘文件可用。
4. 正式试用接入另行审批：保留原播放器回退，不自动切换、替换或重写现有逻辑。DLL 许可证/再分发、安装包、升级兼容仍未完成审查。

原始报告仅保留隔离目录 `lamian-embedded-mpv-spike-20261003` 内的 `seek-matrix-first.json`、`seek-matrix-repeat.json`、`seek-synthetic.json`、`seek-keyboard.json`；没有提交私有媒体路径、数据库或二进制。
