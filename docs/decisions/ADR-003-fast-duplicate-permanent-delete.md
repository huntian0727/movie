# ADR-003：效率优先的重复候选永久删除

状态：Accepted（2026-08-18）

## Context

完整 SHA-256 验证和第二次确认会完整读取本地或网络盘视频，并增加多步交互。用户明确要求恢复高效的一键批量删除体验，并明确接受候选误判导致误删的风险。

## Decision

- 重复候选继续只按 SQLite 缓存的精确文件大小和时长分组，普通浏览不读取视频内容。
- 优先保留目录递归包含全部子目录；每组显式保留选择高于目录推荐。
- 重复页提供“一键永久删除候选移除项”。点击后不计算 SHA-256、不弹确认框，立即永久删除当前页计划中的全部候选移除项。
- renderer 只能提交视频 ID 组成的 keep/delete 计划，不能提交可信路径。主进程必须重新构建当前重复组并校验：组存在、保留项属于该组、删除项属于该组、每组恰好保留一个文件。
- 普通单项/批量删除和扫描异常删除仍保留原有重复候选 guard；只有专用 `duplicate:fast-delete` 通道可执行此产品决策。
- 原 schema v10 完整 SHA-256 后台任务保留为可选安全模式和历史任务兼容能力。

## Consequences

- 同大小、同缓存时长但内容不同的文件可能被永久误删，且快速路径没有撤销能力。
- 文件在数据库分组后发生变化时，快速路径不会重新读取内容或复核 SHA-256。
- 组关系和 ID 篡改会在主进程删除前被拒绝；单个文件删除失败时返回部分失败结果，其余已成功删除的文件不会回滚。
