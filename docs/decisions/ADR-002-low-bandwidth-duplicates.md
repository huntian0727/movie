# ADR-002：低带宽重复候选规则

状态：Superseded by ADR-003（2026-08-18）

## Context

大量源文件位于访问缓慢的映射网盘。内容哈希或打开页面时读取文件会消耗带宽并造成明显卡顿。

## Decision

正式重复候选只按 SQLite 中已经缓存的精确文件大小和精确时长分组。页面查询不读取视频内容，不新增指纹计算；时长未知或元数据失败的文件不进入正式重复组。

候选规则只代表“值得验证”，不证明内容相同。正常浏览重复页面不得读取完整文件。

永久重复清理采用两个独立阶段：

1. 只读验证阶段完整计算候选文件与保留文件的 SHA-256，并将结果区分为“已验证完全相同 / 内容不同 / 无法验证”。该阶段允许取消；取消、失败、离线或读取错误均不得删除任何文件。
2. 只有 SHA-256 完全一致的文件才能进入第二次永久删除确认。验证时持久化完整哈希与强文件身份；删除边界必须对保留文件和每个目标重新完整验哈希。目标先原子移动到同目录、已持久化的随机隔离路径，再按稳定身份和原完整哈希复核，最后再次复核保留文件后才允许永久删除。隔离恢复失败或原路径被占用时不得覆盖或删除，并必须保留可恢复路径证据；应用重启先恢复未完成隔离并使旧授权失效。

快速/低带宽模式只用于候选发现或可恢复操作，不得绕过永久删除的完整内容验证。任何能够在没有成功完整 SHA-256 验证的情况下执行永久重复删除的代码路径，均为发布阻断问题。

## Consequences

- 页面和重复扫描的网络读取最低，允许出现同大小同时长的误候选；误候选必须在只读验证阶段被隔离。
- 永久清理会完整读取参与验证的文件，可能对 NAS/SMB 产生明显耗时；进度、取消和失败必须安全可见。
- 历史 fingerprint schema/代码可为兼容性保留，但不能用于当前分组或文案。
- 用户必须能查看/播放候选，删除安全测试不能因性能优化而移除或弱化。
