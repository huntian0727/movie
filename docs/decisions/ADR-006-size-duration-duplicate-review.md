# ADR-006：重复文件按大小与时长核对

状态：Accepted（2026-10-21）

## 背景

重复候选的既定低带宽规则是按数据库中的精确文件大小与四舍五入到整秒的视频时长识别。对本地、NAS 或网盘挂载的视频逐个读取完整内容并计算 SHA-256 会增加等待时间、I/O 和远端流量，也会让已符合大小/时长条件的候选落入“无法验证”。

## 决策

- 重复判定只使用文件大小与整秒时长：大小必须精确一致，时长按现有分组规则四舍五入到整秒后相同。
- 重复候选核对与清理流程不读取视频内容、不计算完整内容哈希。
- 后台任务仍须复核数据库中的大小、时长、路径和修改时间，并以文件系统元数据核对文件身份/版本；任何缺失、路径变化、版本变化、无法安全隔离或恢复的情况都必须停止删除。
- 永久删除仍需要用户检查保留/删除计划，并在第二次确认中准确输入大写 `DELETE`。同目录隔离、禁止覆盖恢复文件、失败时保留恢复证据等保护继续生效。
- 本决策不重新开放旧的 CloudDrive API 快速永久删除通道、筛选全集快速删除或无二次确认删除。历史 workflowVersion=3 任务仍保持失败关闭。
- 重复组内的单文件手动删除入口保留：点击后只创建该文件的大小/时长核对任务，核对阶段不会删除；核对通过后仍须用户在后台任务中检查计划并输入大写 `DELETE` 二次确认。
- 该规则是低带宽的业务判定标准，不是逐字节内容相同的证明。同大小且同整秒时长但内容不同的视频可能被视为重复项，因此界面必须说明判定依据并要求人工复核候选。

## 影响

- 候选核对不再因完整视频读取/哈希失败而报“无法验证”，对远端存储的读取压力更低。
- 文件系统元数据或文件身份发生变化时仍会停止删除；但此规则不会检测所有可能的“同大小、同时间戳、同身份且内容被原位改写”的情况。
- 自动/一键永久删除依然关闭；本次仅更改重复身份判定和后台核对方式，不自动操作用户的真实媒体。
