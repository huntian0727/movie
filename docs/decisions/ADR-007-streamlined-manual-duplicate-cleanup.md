# ADR-007：重复项手动清理恢复一次确认操作

状态：Accepted（2026-10-21，本地开发版）

## 背景

2026-10-09 的两阶段核对改造将重复文件的快捷删除隐藏在后台任务、额外输入 DELETE 的流程之后，使原来简洁的单项与当前页清理体验退化。维护者要求参照第一次公开打包发行前的体验恢复直接操作，但不回退播放器、异常中心、文件身份、隔离及其他安全修复。

## 决策

- 重复组内任意文件均保留垃圾桶按钮。点击后显示文件名、路径及删除不可撤销的确认弹窗；用户点击一次“确认删除此文件”后，在后台自动完成重复组成员与保留项核对、大小/整秒时长及文件系统状态检查，然后通过现有主进程受管文件删除 API 执行。
- 若当前计划保留的文件是本次目标，须从组内其他文件选择保留对象。保留文件与删除目标绝不可相同。
- 当前页提供“清理当前页”按钮；删除对象是当前页各组计划保留文件之外的其他项。弹窗明确展示当前页码、组数、文件数、大小估算，用户一次确认后自动预检查并按批次执行，显示逐文件失败原因。
- 预检查发现文件缺失、版本变化、身份不符或候选不再匹配，则整次执行被拦截，并刷新数据。不允许由 renderer 传入任意删除路径；主进程依据可信资料库 ID 执行校验，原有受管来源路径、文件类型、大小和修改时间检查继续有效。执行过程中个别失败不会强制删除，结果显示成功/失败。
- 不读取媒体正文，不计算 SHA-256；大小加时长仅是业务候选识别而不是内容逐字节相同证明。
- 高级后台任务“验证当前页 → 等待核对 → 输入 DELETE”仍提供给需要额外审阅的用户，但不再是单项或本页人工确认操作必经环节。
- 不重新启用旧的 `duplicateFastDelete` IPC、CloudDrive API 无确认全筛选批量删除或版本 3 快速清理任务续跑。
- 本决策更新 ADR-006 对手动单文件交互的规定，但不改变其大小/整秒时长判重、不计算哈希及安全复查原则。

## 验收

- 单项取消确认绝不触发删除，确认后仅提交选中一个视频；即使点击计划保留项也要保持其他复制件。
- 当前页批量只作用于本页，且每组保留已选择的一份；超过 IPC 请求上限时分批执行。
- 状态变化、文件不可访问、主进程拒绝时不得误报清理成功。
- 自动化通过只代表 UI 与安全逻辑，**真实网盘文件删除不进行无人值守测试**。开发版自行试用后再决定是否发布。

## 发行边界

仅家里电脑的日常开发版本地更新，保留公开发布暂停。不推送 GitHub、不更新线上正式发行资料。
